# MQTT / V3 Protocol Setup

The V3 protocol uses MQTT for vehicle communication. PyOVMS integrates with the broker by generating and maintaining its password and ACL files automatically — you configure the paths once and the server handles the rest.

← Back to [Production Setup, Step 2](../Readme.md#step-2--v3-protocol--mqtt) · Variable reference: [Configuration](CONFIGURATION.md#v3-protocol--mqtt)

> **Already ran `install.sh`?** It installed and configured FlashMQ for you, including both file paths in `.env`. Skip to [Generated ACL Rules](#generated-acl-rules) or [Troubleshooting](#troubleshooting).

---

## Which broker?

PyOVMS writes Mosquitto-format credential files (`$7$`-prefixed PBKDF2-SHA512 hashes) and Mosquitto-format ACL rules. Two brokers are supported because both read that format:

| Broker | Notes |
|---|---|
| **FlashMQ** | What `install.sh` sets up. Reads the same files via its `mosquitto_password_file` / `mosquitto_acl_file` options. |
| **Mosquitto** | The reference implementation. Reads the files natively. |

Everything below applies to both; the only difference is the config file syntax in Step 2.

---

## How it works

PyOVMS is the central authority for MQTT authentication. It manages two files for the broker:

- **Password file** — hashed credentials for every vehicle, API key, and internal backend client
- **ACL file** — per-user topic rules ensuring each client can only access its own data

Whenever a vehicle, user, or API key is added or changed in the web UI, a background worker rewrites both files — collapsing repeated changes to the same vehicle into a single write.

**PyOVMS does not restart or signal the broker.** It only writes the files; picking them up is the broker's job. FlashMQ re-reads the Mosquitto-format password and ACL files when they change, which is why the automated installer uses it. Mosquitto reloads them on `SIGHUP`, so a Mosquitto deployment needs `sudo systemctl reload mosquitto` after credential changes. Verify this once on your setup: add a vehicle, then try to connect it before reloading anything.

**Who connects to the broker:**

| Client | Username | Password |
|--------|----------|----------|
| Vehicle (V3) | Vehicle ID | Server Password (set in vehicle settings) |
| API key | Key prefix | Full API key value |
| PyOVMS backend | auto-generated usernames | auto-generated passwords |

## Step 1 — Install the broker

**FlashMQ** (recommended — this is what the automated installer uses):

```bash
curl https://www.flashmq.org/wp-content/uploads/2021/10/flashmq-repo.gpg \
    | sudo tee /usr/share/keyrings/flashmq-repo.gpg > /dev/null
echo "deb [signed-by=/usr/share/keyrings/flashmq-repo.gpg] http://repo.flashmq.org/apt noble main" \
    | sudo tee /etc/apt/sources.list.d/flashmq.list
sudo apt-get update && sudo apt-get install -y flashmq
```

**Mosquitto:**

```bash
sudo apt-get update
sudo apt-get install mosquitto mosquitto-clients
```

## Step 2 — Configure the broker

The paths you set here must match `MQTT_PASSWD_FILE` and `MQTT_ACL_FILE` in your `.env`, and the user running PyOVMS must have **write** permission to both.

**FlashMQ** — `/etc/flashmq/flashmq.conf`:

```
listen {
  port 1883
  protocol mqtt
  inet_protocol ip4_ip6
  tcp_nodelay true
}

allow_anonymous false
mosquitto_password_file /etc/flashmq/passwd
mosquitto_acl_file      /etc/flashmq/acl

expire_sessions_after_seconds 60
```

```bash
sudo systemctl restart flashmq
```

**Mosquitto** — `/etc/mosquitto/mosquitto.conf` or a file in `/etc/mosquitto/conf.d/`:

```ini
allow_anonymous false

password_file /etc/mosquitto/passwd
acl_file      /etc/mosquitto/acl
```

```bash
sudo systemctl restart mosquitto
```

Both files are created by PyOVMS on first start — the broker may log a warning about the missing files until then.

## Step 3 — Configure PyOVMS

Generate a `.env` with secure MQTT passwords first:

```bash
python doc/security/generate_secrets.py
```

Then set the following in `.env`:

```dotenv
MQTT_BROKER_HOST="localhost"
MQTT_BROKER_PORT=1883

# Must match the paths configured in the broker config above.
# The user running PyOVMS must have write permission to both files.
MQTT_PASSWD_FILE="/etc/flashmq/passwd"
MQTT_ACL_FILE="/etc/flashmq/acl"

# Backend credentials are pre-filled by generate_secrets.py
# MQTT_BACKEND_METRICS_SUB_PASS="<auto-generated>"
# MQTT_BACKEND_NOTIFY_SUB_PASS="<auto-generated>"
# MQTT_BACKEND_INTERACTIVE_PASS="<auto-generated>"
```

Setting both `MQTT_PASSWD_FILE` and `MQTT_ACL_FILE` is what enables V3 support — with either one unset, the credential sync is silently switched off and no V3 vehicle can connect.

---

## Step 4 — Start PyOVMS

On startup, PyOVMS will:
1. Sync all vehicles, API keys, and backend accounts into the password file
2. Generate the ACL file with per-user topic rules

From this point on, any change made in the web UI is written to both files automatically — see the reload note in [How it works](#how-it-works).

---

## Generated ACL Rules

PyOVMS generates strict, isolated rules for every user and vehicle.

| Client | Allowed topics |
|--------|---------------|
| Vehicle `<vehicle_id>` | Read/write `ovms/<owner>/<vehicle_id>/#` |
| API key `<key_prefix>` | Read/write `ovms/<username>/#` (all vehicles of that user) |
| Karto service | Read-only on specific metric topics across all vehicles |
| Backend service clients | Minimal access scoped to each service's role |

This ensures that a compromised credential can only affect the data of the user it belongs to.

## Troubleshooting

**Vehicles cannot connect to the broker**
- Verify the Vehicle ID and Server Password match what is configured in the OVMS module
- Check that PyOVMS has write permission to both `MQTT_PASSWD_FILE` and `MQTT_ACL_FILE`
- Confirm both paths are set in `.env` — one missing path disables the sync entirely
- Mosquitto only: `mosquitto_passwd -c /tmp/test_passwd testuser` confirms the broker can read a new password file

**Changes not taking effect**
- Confirm PyOVMS is running and connected to the broker
- Check the server log for MQTT sync errors (`LOG_LEVEL=DEBUG` for details)
- If the broker did not reload automatically, trigger it manually: `sudo systemctl reload flashmq` (or `mosquitto`)

**Backend clients fail to connect**
- Re-run `python doc/security/generate_secrets.py` to regenerate the MQTT passwords, then restart both services
